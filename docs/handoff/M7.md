## Config shape (as settled)
Under the category with `"id": "static"` (`"kind": "static"`), key `static` (the old `static.pingOutcomes` is kept and finished):
```json
"static": {
  "fragments": {
    "scripted": "Static IP details (placeholder wording): IP {ip}, prefix /{prefix}, mask {mask}, gateway {gateway}.",
    "gatewayManual": "The gateway was entered manually (placeholder wording)."
  },
  "pingTargets": [ { "id": "gateway", "label": "Gateway" }, { "id": "ip", "label": "IP" } ],
  "pingOutcomes": [
    { "id": "reply",   "label": "Reply received", "fragment": "Ping to {pingTarget} {pingAddress}: reply received (placeholder wording)." },
    { "id": "noReply", "label": "No reply",       "fragment": "Ping to {pingTarget} {pingAddress}: no reply (placeholder wording)." }
  ]
}
```
- `fragments.scripted` (required, may be `""` = nothing is written): placeholders `{ip} {prefix} {mask} {gateway}`. `{prefix}` is the bare number (`30`); write `/{prefix}` yourself. `fragments.gatewayManual` (optional): an extra sentence, written after the scripted line only when the gateway was typed by hand.
- `pingTargets`: ids `gateway` and `ip` must exist (fixed); labels are wording. `pingOutcomes`: ids `reply` and `noReply` must exist; every outcome needs a `fragment` (text, may be `""`) with `{pingTarget}` (the target's label) and `{pingAddress}` (that target's address).
- Context placeholders (`{tech.firstName}`, `{job.number}`, ...) work in every fragment. Any other `{name}` is a schema **warning** and stays as typed. Unknown keys are warnings. Everything else listed is an error.
- Example: IP `1.1.1.1/30`, "Add static IP details" ticked, target Gateway + Reply received gives the note line `Static IP details (placeholder wording): IP 1.1.1.1, prefix /30, mask 255.255.255.252, gateway 1.1.1.2. Ping to Gateway 1.1.1.2: reply received (placeholder wording).`

Session state per static category (plain object, strings and bools): inputs `ipInput prefixInput manualInput includeScripted pingTarget pingOutcome pingConfirmed`; derived `ip prefix mask network broadcast gateway autoGateway gatewayManual ipError prefixError gatewayError gatewayErrorKind canManual ready` (recomputed from the inputs by `StaticModel.Recalc` every time, including after a restore, so a stored or forged derived value is never trusted). Snapshot: `categories.<id>.static = {ipInput, prefixInput, manualInput, includeScripted (0/1), pingTarget, pingOutcome, pingConfirmed (0/1), ip, prefix, mask, gateway, gatewayManual (0/1)}`; only the inputs/flags are read back.

## Decisions where the plan was silent
1. **State = inputs + derived.** The state in the brief (`ipInput, ip, prefix, mask, gateway, gatewayManual, gatewayError, includeScripted, pingTarget, pingOutcome, pingConfirmed`) is kept; I added `prefixInput`, `manualInput` (so the three boxes survive a re-render and a History load), `network, broadcast, autoGateway, ipError, prefixError, gatewayErrorKind, canManual, ready`. `Fragments(state, config := "")`: the model is built from the category; a category Map passed as `config` overrides the wording.
2. **Manual box rules.** It is offered (and stays) when the auto rule failed in a way a typed gateway can fix: IP+1 = broadcast, `/31`, `/32`. It is not offered when the IP itself is wrong (network / broadcast address) or the prefix is below /8 (fix the input). When the auto rule works, the "Enter gateway manually" link reveals it; typing a gateway there overrides the calculated one ("manual" tag, manual sentence in the note). Emptying the box (or "Use the calculated gateway") goes back to auto. A refused manual gateway **does not fall back** to the auto one: the state is not ready. A typed manual gateway is kept when the IP changes and is re-checked against the new subnet (a stale one shows its error in the manual box).
3. **`/31` and `/32` manual checks**: no network/broadcast address exists at /31, so both addresses are valid hosts and the gateway is the other one; `/32` has nothing else in the subnet (so a manual gateway is always refused with "not in the same subnet" or "same as the IP"). The IP must still not be the network/broadcast address for /8-/30 even when the gateway is typed by hand.
4. **`ParseInput` also range-checks the IP** (0.x, 127.x, 224+), so the IP box rejects them; `Parse` alone does not. `ParseInput` returns `ErrorField` ("ip"/"prefix") so each message is shown next to its own box, and a good IP is still reported when the prefix is bad.
5. **IP box normalisation.** After Enter/blur/paste the IP box shows the IP only and the prefix box shows `/30` (also when a dotted mask was typed). A bad input stays in its box as typed. An address typed without a prefix keeps the existing prefix; an address with a prefix replaces it.
6. **Copy button values**: exactly what the row shows (`/30` for the prefix). Toast "<Label> copied".
7. **Used category**: only `includeScripted` or a *confirmed* ping outcome calls `App.UseCategory`. Typing/calculating never does. Typed IP input is held in the session but is **not** "content" (`HasContent`/`HasStructured` ignore it, so the note box is not generated and History is not written for it); it is in the snapshot whenever the call is saved for another reason. Clear All with only static input typed does not ask or save, it just empties the boxes (`Session.HasStaticInput()`).
8. **Ping line independent of the scripted line**, each needs only its own valid address (gateway or IP). A chosen outcome whose target has no valid address writes nothing and shows a red hint on the page. An unconfirmed outcome (M8 prefill) writes nothing.
9. **Copy Notes check only covers "include ticked + invalid"** (as asked). A ping outcome that is not written (no valid address) shows its hint on the page but does not ask at copy time.
10. **Disabled Ping / Ping until success buttons are shown** (dimmed, tooltip `Coming in M8`, no handler) so M8 only has to wire them. Under them: "For now, pick the result yourself after pinging the device."
11. **A "Clear" link** next to the ping result unsets the outcome (a segmented control cannot be un-picked).
12. **Dev sample fragments removed entirely.** `App.AddSampleFragment` is kept as a stub returning false (old callers/tests get false, never a fragment); the M4 selftest puts its static sample straight into the session with `SelfSample("static")`.
13. **Schema strictness**: `static` is now required for the `static` kind (like `entry` for items) and `fragments`, `pingTargets`, `pingOutcomes` are required inside it.
