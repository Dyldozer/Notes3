## How saving, conflicts, locks and OneDrive copies behave (admin's point of view)
- **Save** (button, or Save in the close prompt): pending typing is applied; if nothing changed -> toast "There is nothing to save". Errors -> the Check page opens, a dialog says how many and shows the first; nothing is written. Then the config folder is scanned for conflict copies (below). Then `ConfigStore.Save` (lock, revision check, validate, tmp + verify, backup, keep 20, cache refresh). On success: toast "Saved. Revision N.", status line shows the new revision and "last saved by <you> at <time>", title loses the `*`. The main app notices the new revision at its next call boundary (nothing new in the main app).
- **Locked** by another user/PC (younger than 30 min): dialog "Someone else is saving the configuration right now: <user> on <PC>, since <time>. Try again in a few minutes." Edits stay. An older lock is taken over by `ConfigStore` itself.
- **Changed on disk** since you loaded ("changed by X at T, revision N"): dialog with two buttons, **"Reload (unsaved edits will be lost)"** and **"Keep editing"**. Keep editing leaves everything; Export is the way to keep a copy of your edits before reloading.
- **Folder not reachable**: dialog "The shared config folder is not reachable ... Your edits are still here."
- **Verification failed**: "The new file did not read back correctly, so the existing configuration was left untouched." (any other failure shows the message as is). In every failure the file on disk is unchanged and the lock is released.
- **OneDrive conflict copies**: scanned on load, on Reload and before every save. A banner under the toolbar says "OneDrive found conflicting copies of the config. Check them before saving." and names the files; they are also listed on the Check page. Matches (case-insensitive, files in the config folder only, `backups\` is not scanned): `config (N).json`, `config-*.json` unless it has our backup form `config-YYYYMMDD-HHMMSS[_NN].json`, `config*-<COMPUTERNAME>*.json`, `config*conflict*.json`, `config - Copy*.json`. Before a save with copies present the admin is asked "Save anyway?" (the plan only said to warn; I added the pause). They are **never deleted** by the app.
- **Startup fallbacks**: if the shared file is missing/invalid the store falls back to the cache or the defaults; a yellow notice under the toolbar says which copy you are editing. Saving to an unreachable folder is refused with the dialog above.

## Decisions where the plan was silent
1. **Layout**: left rail with eight pages (Categories, Edit, Note template, Settings, Preview, Check, Files, Raw JSON). The toolbar/status/banners are a header band; the **live note** (composed with the working config, sample call, "mark call details unavailable" toggle, composer warnings) is a footer band visible on every page. The Preview page holds the simulator.
2. **Placeholder chips**: one chip bar per editor page (not one per box). Clicking a chip inserts at the cursor of the last placeholder-capable text box you used (chips don't take focus). If no box was used yet a toast says so.
3. **Controls**: library text boxes (`ax-text`) and plain HTML check boxes / `<select>`s and `<span class="btn">` buttons. One page-wide handler per event ("*" hooks) looks the clicked element up in `AdminHtml.Reg`; ids are readable (`ad_optDel_notDone_reason_r4`) so the self test can find them.
4. **Edits**: text applies to the model 300 ms after the last key and at once on change, and never redraws the page; structural actions (add, remove, move, pick, check boxes that change structure) redraw the page on a 15 ms timer, keeping the scroll position. Invalid structured values (icon, accent, numbers, note prefix > 40) are refused with a toast and a red box / message and leave the model unchanged; free text is never refused (an empty label shows up as a validation error).
5. **Ids** (`Slug`): camelCase of the label, caps words lower-cased (`PWO` -> `pwo`), accents reduced to ASCII (NFD), anything else dropped; empty or digit-first results get a kind prefix (`option2ndRouter`, `step`, `item`); max 32; `UniqueId` appends 2, 3, ... (case-insensitive) and also avoids the placeholder names the composer reads first (`address`, `notes`, `tech`, `job`). Steps and fields share one namespace per category (as the validator requires).
6. **Blocked, not just warned**: a step move that would put a `when` or a stop's `keepSteps` on a step that is not above is refused with a dialog explaining which step depends on which. A move is only refused when it creates a *new* problem.
7. **Removing things**: categories and steps ask first; options/fields/flags/list items go at once (but a referenced option, step or field always lists the references and offers "Delete and remove those references" / Cancel). Cleaning rules: a clause that loses its last option is removed; an `all`/`any` left empty is removed; a `when`/`requiredWhen` left without a condition is deleted; **a flag left without a condition is removed** (a flag needs one); removed step/field `{placeholders}` are deleted from fragments (spaces squeezed); `keepSteps` loses the step.
8. **Last-item rules**: a choice keeps >= 1 option, a group >= 1 field, a steps category >= 1 step, items lists >= 1 action/item, the template >= 1 line, themes >= 1 look; the default look can't be removed; `outcomeRequired` needs an outcome; Yes/No steps keep exactly yes/no (labels editable). Changing a step's type removes the options that no longer fit (references listed first); `reason` must stay a choice.
9. **Static category**: only labels (ping targets, outcomes) and outcome fragments are editable; ids fixed, no add/remove.
10. **Import is refused** when the file doesn't parse, can't be migrated (too new) **or has validation errors** (the summary dialog lists them); the plan allowed showing errors and then deciding - I chose to never load an invalid copy into the working copy (Raw JSON is the place to repair). Applied imports / restore defaults / raw apply keep the loaded revision so the save's conflict check still works.
11. **Admin look** follows the config's *default look* (not the user's `settings.json`), light/dark as that preset says, generated CSS from `Theme.Resolve`. Admin uses the same `Documents\NotesForNFS\config.cache.json` as the main app, so a successful save also refreshes this PC's cache.
12. **Close**: custom `OnBeforeClose` (not `AskBeforeClose`) so the buttons read Save / Discard / Cancel and the self test can answer them.
13. `AdminPreview` always shows only *enabled* categories; a category used in the sample call and then disabled/removed is dropped from the sample note silently.

## Known issues / not done
- **Nothing was looked at.** No screenshots, so spacing, wrapping of long labels in rows, dark mode, the Spectrum band, the icon glyph (Segoe Fluent/MDL2), the disabled-button look, tooltips, and the look of the native `<select>` / check boxes next to library text boxes are unverified. Measured instead: no collapsed text boxes and no horizontal scroll on any page at 1134 px client width (log lines `selftest layout`); smallest text box 58 px wide.
- No real mouse/keyboard: chip insertion relies on `onmousedown="return false"` keeping the caret (tested by setting the selection through the DOM), tab order, Enter in a box (does nothing), real typing + 300 ms debounce, real `<select>` pick, real file dialogs (`FileSelect`; the self test uses a hook) were not exercised.
- Disabled-looking buttons (`reason` Remove, first/last move arrows) are only dimmed; clicking `reason` Remove gives the refusal toast; the move arrows give "already first/last". There is no keyboard shortcut for Save.
- Condition builder works on the flat shapes only (`{step,in}`, `{all}`, `{any}` of leaves); nested ones are read-only + JSON box. A clause whose option list is untouched after the step is removed elsewhere is cleaned only through the delete flow (not by hand editing JSON; that is validated).
- Options/fields/flags/list items have no undo (use Reload to drop all unsaved edits, or Export before a risky change).
- One window update per structural action redraws the whole page (0-32 ms measured); the Edit page for Not Done is ~15 KB of markup.
- The Check page and header counts are recomputed from `Schema.Validate` on every edit (cheap, but not incremental).
- `Schema` warnings about unknown placeholders are shown (Check page and live note) but never block.
- The conflict-copy name patterns are heuristics; unknown OneDrive naming (other languages) would be missed.
- A second admin on another PC can still race (lock + revision check reduce, not remove it - unchanged from M2).

## Manual checklist (a human must do; none of it was seen on screen)
1. Start `NFSAdmin.ahk`: eight rail pages; toolbar Save / Reload / Check; status line "Config folder: ... loaded from shared, revision N, last saved by ..."; the live note at the bottom shows the template with "Sample" and T00000.
2. Categories: ↑ ↓ move, the On check box, rename (id unchanged), icon box (type `E713`: the glyph beside it changes; type `ZZ`: red + toast), note prefix. Add a Steps category and an Items category (name box + Add). Delete a custom one (confirm); delete **Billing**: strong warning with an input, wrong name does nothing, right name removes it, Check shows the error, **Restore Billing** brings it back at the same place.
3. Edit > Not Done: pick steps, move `Supervisor contact (PWO)` above `Order type` (dialog explains it is blocked); `Remove` on Reason is dimmed and refuses; add an option, give it a note text; click a chip while a note-text box is focused (it must land at the cursor); tick "Stops the workflow" on an option and tick/untick kept steps.
4. Remove option `Reason 4`: the dialog lists the flag; "Delete and remove those references" removes it and the flag keeps only the SRO clause. Cancel keeps everything.
5. Conditions: add a clause, switch All of / Any of, tick options, change the step of a clause, remove the condition. In a nested condition (set one through Raw JSON) the JSON box rejects an unknown step and accepts a valid change.
6. Items (Equipment/Billing) lists, switches; Static wording; Note template lines + joiners + chips; Settings looks (invalid accent `blue` is refused with a red message), numbers outside the shown bounds refused.
7. Preview: click options/type text; the footer note follows; "Mark the call details as not available" shows `[not available]`; edit a fragment on the Edit page and watch the footer change.
8. Save: title `*` disappears, revision +1, `backups\` has a copy. Save with the `reason4Sro`-style errors present: refused. Put `config-DESKTOP-X.json` in the config folder: yellow banner after Reload; Save asks "Save anyway?".
9. Two admins: save from another PC (or edit the file) while the window is open: Save offers "Reload (unsaved edits will be lost)" / "Keep editing". Leave a fresh `config.lock` by another user: Save names the holder.
10. Files: Export, Import (a damaged file is refused; a good file asks Replace/Cancel and is not saved), Restore defaults (confirm). Raw JSON: break a bracket (not applied), change a label (applied, dirty).
11. Close with unsaved changes: Save / Discard / Cancel. Main app: after a save, at the next call it shows the new wording.
12. Dark look (set the default look to `spectrum-dark` or edit the preset mode), narrow window (880 px), 150% display scaling.

## How to fill in the placeholder text with the Admin app
1. Close the main app windows if you like (not required) and start `NFSAdmin.ahk`. It opens `config\config.json` next to the program (or the folder named in `nfsnotes.ini`).
2. **Categories** page: rename a category (the name agents see), change its icon, switch it on/off, and set "Text before this part of the note" if you want a prefix like `Not Done - `. Click **Edit** on a row to open its editor.
3. **Edit > Not Done / Close Job** (steps): select a step in the list. Change its **Name**; its **Note text** is a sentence added to the note for that step. Under **Options** type the real wording of every option (name = what the agent sees, note text = what goes in the note). Under **Text boxes** edit the labels. To use what the agent typed or chose, click a **placeholder chip** while the cursor is in a note-text box: `{fieldId}` inserts what was typed in that field, `{stepId}` the option chosen in that step, `{tech.firstName}`, `{job.number}`, ... come from the call. Only the first letter of a sentence is capitalised and a full stop is added if missing.
4. Do **not** worry about ids: they are generated, shown in grey and never change, so saved History entries keep working. New steps/options just get new ids. Leave the Trouble Call stop (`No` on the supervisor question) wording alone unless the business wording changed; the message is the banner, the note text is the limited note.
5. **Edit > Equipment / Billing** (items): edit the item list (Items), the sentence of each action (Actions: `{action} {qty} {item}. {details}`) and the outcome sentences (Billing: only Completed may say "completed"). **Edit > Static**: only the ping target names and ping result sentences (`{pingTarget}`, `{pingAddress}`).
6. **Note template**: the lines of the note (`Notes: {notes}` is where all categories go), the text for unavailable values, and how sentences and categories are joined.
7. Watch the **live note** at the bottom (and the **Preview** page: pick options, type text) after each change; the Check page lists errors and warnings (an unknown `{placeholder}` is a warning and stays visible in the note).
8. Press **Save**. The title loses the `*` and the revision goes up; running copies of the main app pick it up at their next call. If something goes wrong, **Files > Export** keeps a copy of your edits and `config\backups\` holds the last 20 saved versions.

## Opus review (2026-10-11)

- **Incident: the M10 run closed the user's open NFS Notes window.**

  - The first normal launch takes a per-user named mutex (`Local\NFSNotes_<user>` / `Local\NFSAdmin_<user>`).
  - A second normal launch brings the running window to the front (restoring it if minimised) and exits. The running copy and its call are never touched.
  - A `--selftest` run never takes the mutex and runs alongside a running copy, on its own temp folders.
  - Verified live:
    - A second `NFSNotes.ahk` exited by itself (code 0) while the first kept running.
    - A full `NFSNotes.ahk --selftest` ran to completion (code 0) while the first kept running.

    - All closed cleanly afterwards, and no processes were left.
  - Trade-off: after changing the code, close the running copy (or use the tray's Reload) before launching again. A relaunch no longer replaces it.
