## How the Spectrum look is loaded: GENERATED, not `themes\spectrum.css`
The library can load a `.css` by path and honours `/* @extends win365 */`, but `AxGui.SheetName()` names the body class after the file and answers `win11` for anything that is not one of its own 18 looks. A `spectrum.css` would therefore get `body.sheet-win11`, and every `body.sheet-win365 ...` rule of the base would be dead. (The library may not be edited, and `lib\themes\` is not ours.) So there is **no `themes\spectrum.css`**: the preset sheet `spectrum` means *the library's `win365` + CSS generated in `Theme.Css` and applied with `SetExtraCss("nfstheme", css)`*. The extra CSS is inserted before the library's accent sheet; where it must beat the library (accent fills, rail pill, title bar, fonts) it uses `!important`.
- Navy `#003057` title bar (not when the window is inactive: win365 drains the band then) + a 3 px accent strip (`inset` shadow, so the bar height and the page layout are untouched). Plain looks get a band made from the accent that carries white text at 4.6:1.
- IE11: no `var()`, no grid, no `gap`; colours are written as `#RRGGBB` / `rgba()`; a test scans every colour-bearing declaration (90 look x accent x font x size combinations).
- The window is built with the resolved sheet/mode/accent and the extra CSS queued in `<head>` before `Show()`, so the first paint already wears the saved look (no light-then-dark flash). Not seen on screen.
- Presets (`themes.presets` stays the admin's list): `spectrum-light`, `spectrum-dark` (sheet `spectrum`, `#0099D8`), and `win365` ("Microsoft 365 (plain)", `#0F6CBD`). Other library look names in a preset pass straight through; an unknown name falls back to win365 with a warning.

## Settings page
- **Look** (dropdown of the config's presets), **Mode** (Light / Dark / System), **Accent** ("Use the look's colour" / "Custom colour": 8 swatches, Spectrum blue first, plus a `#RRGGBB` box; anything else shows "Use a colour like #0099D8" and is never applied), **Font** (only the allowed fonts that are registered in HKLM/HKCU `...\Fonts`; Segoe UI always), **Text size** 9-20.
- Every change previews on the whole window at once (nothing saved). **Apply** saves, **Revert** returns to the saved look, **Restore defaults** (asks) resets the five appearance settings and applies them. "Unapplied changes" bar + dimmed Apply/Revert when clean.
- Leaving the page or closing the window with an unapplied draft asks "Keep these appearance changes?" (Apply / Revert; Escape = Revert). The close path never blocks the close.
- **Window**: "Keep on top" (two-way with the title-bar pin) and "Open History panel at start" (`historyOpen`; follows the footer History button too). **About**: version, config source + revision (+ warnings), data folder + "Open folder" (runs `explorer.exe "<Documents\NotesForNFS>"` on that fixed path only), log level.
- Title-bar toggle: always an explicit Light or Dark (also from System), saved at once; other pending changes stay pending.
- Mode "System" is resolved to light/dark by reading `AppsUseLightTheme`; the library is only ever given explicit light/dark. It is applied at startup/Apply and re-checked every 30 s (`TickClock`); there is no live notification.
- Logo: shown in the title bar only if `assets\logo.png` (or `.svg`) exists. None exists; none is created or fetched.

What was fixed (the guarantee is by construction, then confirmed on the DOM):
- Text colours on accent fills are chosen by contrast (white or `#111111`); if neither reaches 4.6 the fill is nudged (e.g. custom `#7A5AF8` button fill becomes `#7758F2`).
- Accent used as text (links, tile number) is pushed lighter/darker until it passes against every surface it can sit on; so `#003057` stays readable on dark and `#FFD200` on light.
- Muted greys, reds, tag fills (darkened until white text hits 4.6; the amber tag uses dark text), banner/hover/selected tints (text >= 7:1 on the tint) are all computed. The old `opacity: .6` muted text is now an explicit colour, so the ratio is real.
- Found by the unit tests before the DOM run: the technician card and calls tile used a grey wash on which Spectrum blue at 30 px was only 2.9:1; both now sit on the card colour (3.21:1 on white).
- The only failure the DOM run raised was the dimmed, disabled Apply button (opacity .45). Disabled controls are exempt, so it is measured with the dim removed. No generated-CSS change was needed beyond the above.

## Decisions where the plan was silent
1. **No `themes\spectrum.css`** (see above); the look is a preset sheet name resolved in code.
2. **Mode default is "" = the look's own mode** (so `spectrum-dark` is dark with no setting); `light`/`dark`/`system` are explicit. Choosing another look in the dropdown resets Mode to that look's own unless Mode is System. Choosing the look's own colour by hand is treated as "use the look's colour". Old files: `theme` -> `mode` (only when `mode` is absent), then dropped on the next save.
3. **Text size scale**: 12 (default) = the library's normal 14 px, i.e. `px = Round(size * 7/6)` (9 -> 11 px, 20 -> 23 px), so default looks unchanged. All app sizes are `rem`; library controls get an explicit px.
4. **Fonts** stack: chosen font, Segoe UI, sans-serif (the default stack is Segoe UI Variable Text, Segoe UI). Icon fonts are untouched (`.btn.icon`, caption buttons are excluded from the font rules).
5. Appearance save always writes (the selftest's Settings is a temp folder), so `MainWindow.Persist` is now always true.
6. `Restore defaults` resets only preset/mode/accent/font/size (not pin, history-at-start, window, last page).
7. A saved preset id that no longer exists is kept in the file but logged once (WARN) and shown as the default look; the Settings page treats them as equal (not dirty).
