## Decisions where the plan was silent
1. **Field ids are one namespace per category** (they are the `{placeholders}`): the schema rejects a field id used in two steps or equal to a step id. That is why the TC field is `supervisorNameTc`, not a second `supervisorName`.
2. **`{<stepId>}` = the chosen option's label; `{<fieldId>}` = the typed text.** An unanswered visible choice has an empty label and an empty field is `""`, so a template never produces an "unknown placeholder" warning for a step that is merely unanswered.
3. **Text / group steps speak only when a field has text** (or the step has no fields). A choice/yesno step speaks only when an option is chosen: option fragment first, then the step fragment. So an optional untouched text step adds nothing to the note. Optional text that belongs to a choice (contact details) is best placed inside the option fragments as `{contactDetails}` (the defaults do); an empty value just disappears in the composer's normalisation.
4. **Sentence case only touches the first character of a fragment** (M4 rule), so `Contact 1 placeholder note. left a message.` keeps the typed lower case. The agent types as it should read.
5. **Step `required` defaults to false** when absent. For a `text`/`group` step, `required: true` means at least one field has text. Field-level `required` / `requiredWhen` are separate.
6. **Locked steps are shown but excluded from everything**: validation, fragments, values, and flags (a flag about an answer that is not in the note would only be noise). Hidden steps are excluded from the same four.
7. **A step's `when` may only refer to EARLIER steps** (schema error otherwise; the engine treats a forward or self reference as false). `requiredWhen` and flags may refer to any step of the category.
8. **`yesno` has exactly two options, ids `yes` and `no`** (labels free). `group`/`text` have no options (schema error); `group` needs at least one field; a `text` step without fields is a warning.
9. **Stop `keepSteps` is optional** (default: keep nothing) and the stop step's own option fragment is NOT used (the stop `fragment` replaces it). A kept step that is hidden contributes nothing.
10. **Which categories Copy Notes checks**: used steps categories that HAVE answers. After "Reset this category" a category stays "used" for stats, but with no answers it adds nothing to the note, so it is not validated. Message: `"<Label> is missing: a, b. <Label2> is missing: c. Copy anyway?"`; Yes copies, No jumps to the first incomplete category's page. Nothing else (Clear All, History, new call) is ever blocked.
11. **Hints** ("This is required." / "Choose an option.") appear for a step the agent has touched (picked an option, or left one of its text boxes) or after a Copy attempt with missing items; never while typing in the first box of a step.
12. **Rendering policy** (also in the StepsView header): the list is rebuilt only when the visible-step structure or the stop changes, or on a forced refresh (reset, new call, Clear All, History load, config change). Everything else is patched in place and a text box with the focus is never overwritten. Typing is committed 250 ms after the last key and at once on change/blur; `Flush()` (called from `MainWindow.SyncNote` and Copy) commits pending text and the focused box only, so a stale DOM can never overwrite loaded answers.
13. **Controls used**: `<ax-card>`, `<ax-segmented>` (yes/no, or <= 4 options), `<ax-radio>` (> 4 options), `<ax-text>` / `<ax-textarea>` - the same tags `AddCard / AddSegmented / AddRadio / AddEdit` write - put into ONE mount point (`g.AddHtml`) by setting `innerHTML` and calling `AxTags.ExpandIn(list)`. Reason: a page container cannot be emptied or re-ordered after `Show()` (only appended to by `_LiveAdd`). Choices are heard with `g.OnValue(id)`, text with `g.On("keyup"|"change"|"focusout", id)`; both are registered once per config id in `Wire()`. Option labels go through `StepsView.Lbl` (`|` -> `/`, `:` -> U+A789) because the tags read `id:Label|id:Label`.
14. **Locking** is CSS (`opacity .42; pointer-events:none`) plus `disabled` on the inputs of locked cards.
15. **Dev "Add sample fragment"** is not built for steps categories; `App.AddSampleFragment` returns false for them. The M4 selftest therefore uses Equipment/Static for its sample fragments (log keys renamed `billingAfterEquipment`, `railEquipment`).
16. **Old `Answers` semantics changed**: before M5 `Session.Answers` doubled as the values store; it is now the engine's answers and the composer values live in `Vals`. `Values/ValuesFor/SetValue` behave as before. Snapshot `categories.<id>.values` is still the Composer values.
17. A restored (History) call keeps its stored fragments/values exactly (no engine re-run on load); the pages are drawn from the restored answers with the CURRENT config. If the config changed, unknown ids are ignored and listed by `Warnings`.

- If the agent clicks an option while a different text box still holds uncommitted typing, the blur commits it first; a mouse paste followed by Copy Notes is covered by the focus check in `Flush()`. ## Filling in the placeholder text
Edit `config\config.json` (a copy of the defaults) and **raise `"revision"` by 1** each time so running apps pick it up at the next call. Everything below is under `categories` -> the category with the given `id`.

Replace freely (these are the placeholders):
- `notDone` / `closeJob`: `label` (the category name), and in every entry of `steps`: `label`, each `options[].label` and `options[].fragment`, the step-level `fragment`, each `fields[].label`.
- `notDone`.`flags[0].message` (the placeholder warning text) and, if you want other compatibility warnings, add more `flags` entries (a warning only, it never blocks).
- The Trouble Call stop (`supervisorTc` -> option `no` -> `stop`): `message` is the banner, `fragment` is the note sentence. Both already hold the real wording from PLAN 3.6; change only if the wording changes.
- Fragments are templates: write the sentence as it should read. You may use `{tech.firstName}`, `{tech.id}`, `{job.number}`, `{job.workOrder}`, `{address}`, `{<fieldId>}` (what the agent typed in that field) and `{<stepId>}` (the label of the option chosen in that step). Only the first character of a fragment is capitalised and an end full stop is added when missing, so type the text with the capitals you want inside it. An empty fragment `""` adds nothing.
- Reason / Contact / Outcome lists: you may add, remove or reorder `options`, as long as each has a unique `id`. If you remove an option, also check no `when` / `requiredWhen` / `flag` refers to it (the validator only warns about an unknown option id in a condition). Up to 4 options are drawn as a segmented control, more as a radio list.

Do NOT change:
- **ids**: every `id` of a category, step, option, field and flag (the notes of calls already saved in History refer to them), especially the required step `reason`, the system category ids (`notDone`, `equipment`, `billing`, `static`, `closeJob`) and their `kind`.
- **`yesno` option ids** `yes` and `no`, and the order-type option ids `pwo`, `tc`, `sro` (the supervisor steps' `when` use them).
- **Conditions**: every `when` / `requiredWhen` / flag `when` (they reference step and option ids; a step's `when` may only look at an EARLIER step).
- **`stop.keepSteps`** (`["reason", "orderType"]`): ids of steps that come before the stop step.
- Field ids must stay unique inside a category (they are the `{placeholders}`): `supervisorName`, `rescheduleReason`, `supervisorNameTc`, `contactDetails`, `closeNote`. If you rename one, rename its `{...}` in the fragments too.
- The `required` / `requiredWhen` / `multiline` / `type` keys unless you intend to change how the step works.

After saving, the app checks the file on the next call boundary; a file that fails validation is ignored (the app keeps the last good copy and shows the warning chip).
