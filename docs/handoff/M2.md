## How it behaves
**Load order.** SharedDir set: read -> parse -> migrate -> validate; on success the cache `config.cache.json` is written atomically and used (`Source="shared"`). Missing/unreadable/malformed/invalid/too-new/unreachable shared -> warning + cache (`Source="cache"`) -> else defaults (`Source="defaults"`) with a warning. SharedDir empty: cache if valid else defaults, no warning, `SharedConfigured=false`.
**Chip text** (`ChipText()`): `config: shared r12`, `config: cache r12 (warn mark)`, `config: defaults (warn mark)`, `config: local`, `config: local r12`. Warn mark is `Chr(0x26A0)`. `ChipTip()` joins the warnings with `; `.
**Save** (admin): needs SharedDir; lock `config.lock` {user, machine, time} (other user + younger than 30 min -> refused naming holder; older or unreadable -> taken over with a log warning; same user -> re-entrant); optimistic revision check against the file on the share ("changed by X at T ... Reload first"); validate; revision+1, updatedAt, updatedBy; write `config.json.tmp`; re-read and compare; back up current file to `backups\config-YYYYMMDD-HHMMSS.json`; keep newest 20; `FileMove` over the original; refresh cache; lock released in `finally`. Failures delete the `.tmp`, leave the original, and return `{Ok:false, Error}`.
**Settings.** theme (light/dark), accent (`#RRGGBB` or `""`), fontFamily, fontSize 9-20, window `{x,y,w,h}` (`""` = unset), alwaysOnTop, historyOpen, lastPage. `Set` returns false on invalid input and changes nothing. A corrupt file is renamed `settings.bad-<stamp>.json` (defaults used, warning). Individually invalid fields in an otherwise valid file are reset with one warning each.

## Decisions where the plan was silent
1. **AxJson writes booleans as 1/0 and sorts Map keys.** `ConfigJson.Stringify` post-processes a fixed list of boolean key names (`enabled system required sentenceCase alwaysOnTop historyOpen qty details`) into `true/false`; adding a new boolean key to the schema means adding it to `ConfigJson.BOOL_KEYS`. Keys in files are alphabetical (`id` after `fragment`), arrays keep order. The validator treats bool fields as integers 0/1 (what the parser yields), so 1/0 and true/false both load.
2. **Condition shape / fields.** `when` and `requiredWhen` are `{step, in:[...]}`, `{all:[...]}`, `{any:[...]}`; unknown option ids in `in` are a warning only. The Trouble Call stop lives on the option: `stop: {message, fragment}` (message and limited-note text taken from PLAN 2 / 3.6). `yesno` steps must have option ids `yes` and `no`.
3. **Items categories** keep their lists under `entry: {actions[], items[], outcomes[], qty, details}`; static category under `static: {pingOutcomes[]}`. Equipment `items` has one placeholder item (the plan names none).
4. **Ids** match `^[A-Za-z][A-Za-z0-9_-]*$` (hyphen allowed because of `spectrum-light`). Icon codes are 4-6 hex chars. Unknown top-level keys are warnings.
5. Required `contextFields` ids are enforced (techName, techId, address, jobNumber, workOrder).
6. System categories must keep their kind (notDone steps, equipment/billing items, static static, closeJob steps); `system:false` on one of them is a warning.
7. Backup names: `config-YYYYMMDD-HHMMSS.json`, same-second collisions get `_02`, `_03`... (one past the highest existing index, so pruning can never free a name that sorts before newer files). First save with no existing file makes no backup.
8. `CheckForUpdate` also returns true when the store is on cache/defaults and the shared file is valid again, even at the same revision, so recovery clears the warning chip.
9. Lock "same user" is by `User` only (not machine). Lock times are local clock; a skewed clock on another PC could shorten/lengthen the 30 min window.
10. The window rect is saved as "what to ask AxGui for", not the raw rect: the real window is 14 px bigger than the requested Width/Height here (frame), so `MainWindow.Calibrate()` measures the difference after Show and subtracts it on save (verified: no creep over restarts).
11. Log lines use the file name, not the full path, to keep user profile names out of the log.

## Known issues / notes
- `DirExist(SharedDir)` and the read are synchronous in startup. A dead UNC path can stall the app start for however long Windows takes to give up. Consider moving the load off the UI thread or a short pre-check when the shared path is deployed.
- `FileMove` over an SMB share is not truly atomic (as in PLAN 8); the temp file + verify + backup mitigates it.
- Two admins saving in the same instant can both pass the lock check on a flaky share; the revision check afterwards reduces but cannot remove that.
- Tooltips for the chip join warnings with `; ` (I did not verify how the library renders a newline in `data-tip`).
- Gotchas hit while writing tests: a static class variable named `Base` breaks the class (AHK built-in); a local named `t` clashes with test class `T`; closures capturing `for` loop variables were unreliable here, so `TestSchema.With(fn, args*)` passes values explicitly.
- Sheet name `spectrum` in the theme preset does not exist yet (M9 creates `themes\spectrum.css`); the validator only requires non-empty text.
- Settings has no UI yet (M9); `accent`, `fontFamily`, `fontSize`, `historyOpen` are stored/validated but not applied.

## Manual checks (a human must do)
1. Run `NFSNotes.ahk` with empty `SharedPath`: chip reads `config: local`. Hover it: tooltip mentions the local copy.
2. Make a folder with a copy of `config\config.default.json` as `config.json` (set `revision` to 12), put its path in `nfsnotes.ini [Config] SharedPath=`: chip reads `config: shared r12`, no warning mark.
3. Rename/damage the file or point at a missing folder: chip reads `config: cache r12` + warning mark; the tooltip lists the reasons. With no cache either: `config: defaults` + mark.
4. Toggle dark, pin, move/resize the window, switch to Billing, close, reopen: all restored. Move the window to a second monitor, unplug it (or edit `%AppData%\NFSNotes\settings.json` to x=-9000), reopen: window appears on the visible screen.
5. Corrupt `settings.json` (type garbage): app starts with defaults and a `settings.bad-*.json` appears next to it.
6. Look at the logs: `config loaded` / `config ready` lines, no names or job numbers.

## Opus review (2026-10-10)

**Change: the config lock is now atomic** (`src\Config\ConfigStore.ahk`).
- The lock file is created with Win32 `CREATE_NEW`, which fails if it already exists. Two admins racing for a free lock can no longer both take it. A stale or corrupt lock is deleted and then re-created the same way.
- A lock counts as "ours" only for the same user **and** the same machine. The same user saving from a second PC is now refused, and the message names that machine.
- Release deletes only our own lock. It no longer deletes a lock it can't read.
- New tests cover a second create failing, the first holder's content surviving, and the same user on another PC being refused. The suite is now `TOTAL 446 PASS 446 FAIL 0`.

## Change after review: deployment layout (2026-10-10, user decision)

The app is distributed from a shared OneDrive folder.
- **Admin config:** `config\config.json` beside `NFSNotes.ahk`. `nfsnotes.ini` `SharedPath` is now only an optional override. A starter `config\config.json` (a copy of the defaults, revision 0) was added.

- **Config chip:** hidden for agents and shown only when there are warnings (a fallback to cache or defaults). It is always shown in dev mode. The selftest logs `chipHidden`.
