## Decisions where the plan was silent
1. **Clock**: services take `Now` = function returning a 17-digit stamp (`YYYYMMDDHH24MISS` + 3 ms digits; the ms part is optional). Debounce: an event is ignored when `0 <= elapsed < DebounceMs` since the last counted event, so debounce 0 never ignores by time and a clock that moved backwards (DST/clock change) does not block counting.
2. **Stats API shape**: `Summary()` returns `{Items:[{id,label,count}], Total}`. Order: enabled configured categories, then ids found in records that the config does not know (sorted, label = id), then Uncategorized. Disabled categories with records are omitted from the list, so the list can sum to less than Total (the records still count in Total).
3. **Stats location**: `CallStats({Dir})` appends `\stats`. App passes `Util.UserDataDir()` (temp folder in `--selftest`). Agent = `A_UserName`. File format as specified; keys sorted by the JSON writer.
4. **After restart** there is no current record until the next counted event, so category use then is not credited (documented in the class header). The current job number is in memory only.
5. **Records belong to their event date**: a category used after midnight but before the next event is credited to the previous day's record and that day's file is rewritten.
6. **Mock states reset on a new call** (new call = new data); Duplicate/Burst do not change them. `SetHealthy` also raises OnContextChanged so the dot redraws.
7. **Manual entries** live in the App's working `CallContext`. A provider update never overwrites them unless it has a real value; a counted new call drops them. A manual entry's value is registered with the log redaction. Ids are not changed by manual entry; `CallSession.Context` is refreshed with a clone.
8. **Card tags**: every field shows a small tag (Live, Mock, Manual, Unavailable, Stale, Empty, From history). Unavailable/empty/stale values are dashed-underlined and clickable. Field order on the card: Name, ID, Job, WO, Addr (labels fixed in code for now, not from `contextFields`).
9. **Dev panel** is a popover on the "Dev" title item (`Popover: {Build, OnOpen}`), buttons are markup routed by `g.On("click", id)`. It redraws itself after each action.
10. **Rail dot** is CSS on `.nav-item.nfs-used:after` (amber, white ring), toggled by class on the nav item; the library has no badge API. Category pages get a "Mark used (dev)" button only in dev mode (`nfsUse_<categoryId>`); `App.UseCategory(id)` is what M5/M6 views should call.
11. **Config between calls**: `HandleNewCall` (counted only) calls `CheckForUpdate()` then `ApplyPending()`, updates `Stats.DebounceMs`, logs `config revision changed from/to`, refreshes chip, card, tile. Popover labels are built per open so they are always current. The 5-minute timer only calls `CheckForUpdate()` and logs `config update pending` once per revision. The rail items themselves are still fixed (M5+ should build them from config).
12. **Tile midnight refresh**: a 30 s timer redraws the tile when the date changed (not in selftest).
13. **A debounced/ignored new-call event** does nothing to the session or notes (only OnContextChanged may have refreshed the card).
14. `Log` special keys: `Log.SENSITIVE_KEYS` still masks by key name; stats and session never log values.

## Known issues / notes
- Stats are per PC and local; two apps (two Windows users) each have their own files. The agent name is stored in the file, not the job or tech.
- `CheckForUpdate()` reads the share on the UI thread at each counted call (cheap for a local OneDrive copy; a dead UNC could stall that call).
- A comparison `"2026-01-01" < "2026-07-12"` throws in AHK v2 (non-numeric strings); use `StrCompare`. Hit in the prune code.
- AHK gotcha hit again: a local named `t` in a test shadows class `T` (the whole test then fails with "variable not assigned").
- A line that starts with an identifier is a new statement, not a continuation: start continued string expressions with `.` (this broke the health-dot HTML once).
- Rail items and the card labels are not yet driven by config (`contextFields`, categories order/enabled); Not Done etc. pages are still placeholders.
