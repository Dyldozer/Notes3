## Tests run
`AutoHotkey64.exe /ErrorStdOut tests\RunTests.ahk` -> `TOTAL 54 PASS 54 FAIL 0` (exit code 0). Covers AtomicWrite (round-trip incl. UTF-8, overwrite, empty, failed write leaves original intact, no .tmp left), redaction (registered values case-insensitive, longest-first, sensitive keys in object and Map, IP kept, log file never contains the registered values), level filtering, rotation (Keep=3 gives .1-.3 and no .4), default path.
Note: a first run had 4 failures that were a test-script bug (local var `log` shadows class `Log`, names are case-insensitive); fixed by renaming the local to `lg`. **Do not name locals `log` in code that uses the `Log` class.**

### Notes-panel spike: WORKED (approach A, no fallback needed)
`g.Footer(html)` (AxWindow.Bands.ahk) pins raw HTML under the rail+page area, outside the page container, so one textarea (`#nfsNotes`) plus History / Clear All / Copy Notes buttons exist exactly once and survive page switches. Likewise `g.Header(html, {Under:false, Drag:false})` holds the Technician card and Calls-today tile above the rail. The page area gets the remaining height automatically.
Evidence (`--selftest`, logged programmatically through COM): set text, switched through all 6 pages, after each: `current=<page> notesKept=1 notesVisible=1 footerH=110`. This proves the text persists and the element is laid out with non-zero height; it does not prove it looks right.
Caveats: the footer spans the full width (under the rail too), so the layout differs slightly from the PLAN sketch where notes sit right of the rail. The notes controls are raw HTML, not `Add*` controls: handlers use `g.On("click", id, fn)` and the text is read via `g.El("nfsNotes").value`. They rely on the win365 `.btn` / `.textbox` classes; styling not visually verified.
Buttons: Copy Notes -> `A_Clipboard` + Toast (no verification yet, M4). Clear All -> `Confirm` then clear (Toast "Nothing to clear" if empty). History -> Toast "History - coming in M4".

### Hover popover: wired, Build verified, hover itself NOT verified
`g.Popover("nfsCalls", {On:"hover", Align:"right", Width:200, Build: fn})` on the Calls-today tile. `Build` returns dummy per-category counts, total, and "opened N time(s)". Self-test called `ShowPopover` twice: first open contained "opened 1", second "opened 2" (rebuilt each open). A real mouse hover was not exercised.
Gotcha found: `Popover()` called before the window is shown throws (`_pop` property missing in AxWindow). It must be registered once the window is ready, so it is registered inside the `OnReady` callback.

### documentMode check: works
`g.DocMode` read after ready; logged `documentMode=11.0`. If `< 11`, an `Alert` explains the `FEATURE_BROWSER_EMULATION` key. The Alert path itself was not triggered (this PC is already at 11; HKCU key `AutoHotkey64.exe = 11001` is present). Not yet tested on a locked-down work PC (still an M1 acceptance item).

## Known issues / notes
- `Log` is also the name of AHK's built-in `Log()` function; the class shadows it fine, but any local variable called `log` will break (see above).
- Window layout: header and footer heights are fixed by content; with `MinHeight 560` the page area is ~300 px at minimum size. Needs a human check.
- `ThemedCss`/dark-mode tuning of the custom header/footer CSS uses neutral `rgba(128,128,128,x)` borders so it should work in both themes; not checked visually.
- History dedicated pop-out, config chip states, dev panel, real stats: later milestones.
- `--selftest` is a small developer hook kept in `MainWindow.RunSelfTest`; harmless in production.
