## Decisions where the plan was silent
1. **Nothing is generated for a fresh call.** The box stays empty until a category is used or a fragment/value exists (`CallSession.HasStructured()`); otherwise the template lines would make every call "have content" and Clear All on an empty call would save an entry. Once something exists the full template renders (also with an empty `Notes:`).
2. **Empty `{notes}`**: the brief said both "renders `Notes: `" and "trim trailing spaces"; the line is trimmed, so it renders `Notes:`.
3. **Sentence case** uppercases the first *character* of a fragment (so `5 ports` is unchanged, `mcKenzie ...` -> `McKenzie ...`). End punctuation is added unless the fragment ends in `.`, `!` or `?` (a trailing comma gets a period after it: `x,.`). Dedupe compares the normalised, punctuated, lower-cased text, inside one category only.
4. **FirstName** also title-cases after `.` (so `J.R. SMITH` -> `J.R.`), besides `-`, `'` and the curly apostrophe. A word with no letters is returned as typed.
5. **Context statuses on restore**: every field with a value becomes `history`. A field that had no value stays `unavailable` / `empty` (the `CallContext` rule forbids a valueless `history` field and the composer needs `unavailable` to print the unavailable text).
6. **`restoredFrom`** is the id of the History entry the *current call was loaded from*, written on any entry saved while that call is in the session (including the `beforeRestore` entry made when loading over it). It is not stored in the snapshot.
7. **Save failure on a new-call event**: the event is *not counted* and the session is not reset (the call is kept), an error toast tells the agent (Clear All retries the save). This needs the pre-check `CallStats.IgnoreReason` so a debounced duplicate never saves anything. Side effect: the provider's `OnContextChanged` (raised just before `OnNewCall` by the mock) already refreshed the card to the new tech while the note and session still belong to the old call; the composer uses the session's own context so the note stays correct.
8. **A loaded call keeps its context**: while a History call is loaded, provider context updates are ignored (`App.HistoryLoaded`) until the next counted new call; otherwise live values would replace the "From history" ones under a historic note.
9. **Agent-edited detection** = box text != `GeneratedText` (CRLF-normalised) after library hooks (`keyup`, `change`, `focusout` on the box) plus document-level `oninput` / `onpaste` / `oncut` attached directly (the library's `g.On` has no input/paste/cut), checked 20 ms later. Session saves re-read the box, so a missed event can't lose text. Regenerate never runs in a way that overwrites a differing box unless the flag says it is unedited.
10. **Bar text**: "Your edits are kept. [Regenerate] (replaces your edits)"; the confirm is "Replace your edits with the generated note?" with buttons "Replace" / "Keep my edits". The bar adds about 28 px to the footer while shown (the page area shrinks by that).
11. **History panel interaction (as built)**: raw markup rows `nfsHR_<n>`; **double-click loads** through `g.On("dblclick", id)` (supported by the library, verified with a fired DOM event); single click selects; a Load button loads the selection (no double-click needed). Hover preview = library `Popover` (`On:"hover"`, registered per row id, rebuilt on every open); no `title` fallback was needed. `AddDataView` was not used (it can't live in the footer band). List capped at 300 rows per day.
12. **Window growth** uses `WinMove` on the real window: grows by exactly `PANEL_H` (260) unless the work area is shorter (then capped / moved up via `Util.FitRect`). Skipped when maximized or minimized (the panel then just takes space from the page area). The remembered window height excludes the panel's growth, so `historyOpen` restoring (done 120 ms after start) never makes the window creep.
13. **History location in `--selftest`** is the same temp root as stats (`App.StatsRoot`), deleted at the end.
14. **Retention** semantics match stats: a file dated exactly `RetentionDays` days ago is kept, older is deleted; `Days()` hides older files even before the prune; a config change applies at the next counted call (`ApplyConfigBetweenCalls`).
15. **Snapshot** is `{context, categoriesUsed, categories (only with fragments or values), noteText, generatedText, agentEdited 0/1}`; categories without content are left out so Restore -> Snapshot is the identical tree. Session `Answers` is kept as the values store (`Values`/`ValuesFor` are aliases) so M3 code and tests are unchanged.
16. **Composer warnings** are shown only in dev mode (a small line under the notes box) and logged at debug as counts; they contain placeholder names and category ids only.

## Known issues / notes
- Nothing visual was verified (see above). CSS for the panel/bar/list uses neutral `rgba(128,128,128,x)` colours; the selected-row tint is a fixed Spectrum-blue rgba.
- The `<select>` (day) and the search `<input>` use the library's default look inside the footer; the `.textbox` wrapper is what the notes box uses.
- Popover on rows: the library places it below the row or flips above; a long note is limited to 360 px wide with wrapping, no max height.
- Because the box stays empty until something is used, the technician name/ID/job lines don't appear until the first category is used.
- `Composer` ignores categories the config doesn't know (warning only). Rail items are still fixed in code (M5+).
- Copy Notes with an empty/whitespace box shows "Nothing to copy" and doesn't touch the clipboard.
- After a failed save on a new-call event the tile count is unchanged for that event (it was not counted); this is a deliberate trade-off (decision 7).
- Gotchas hit: the panel id collided with the History *button* id (`nfsHist`); renamed the panel `nfsHistPanel`. Closures stored as object properties receive `this` as first argument when called as methods (`clk.Add(sec)` needed `(self, sec)`). `bash` heredocs with `'''` break; used the Edit tool.
